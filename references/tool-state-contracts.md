# 工具与状态契约

当任务涉及新增工具、外部副作用、恢复或成果组合时读取。按现有系统落地，不要求照抄字段名或建立新数据库。

## 任务与工具应表达的身份

| 内容 | 需要解决的问题 |
| --- | --- |
| 任务目标与交付 | 输入范围、允许动作、验收依据、截止/停止条件是什么？ |
| 当前主体与范围 | 宿主如何重新取得当前权限？如何防模型参数改变租户/项目？ |
| 来源与观察 | 来源版本/哈希、单位、定位、选中观察、分页范围如何绑定？ |
| 动作 | 目标记录、规范参数、动作身份、现有批准范围、已发送与否如何区分？ |
| 结果与产物 | 文件/外部记录是否存在、内容是否相符、覆盖是否完整、如何授权取得？ |
| 恢复 | 已确认步骤、可能发生的副作用、待核状态、租约/预算如何持久保存？ |

运行ID、随机观察句柄和日志指纹用于追踪；可复用事实快照应由规范来源、版本、规则、范围和适用权限产生。不要让每次运行随机值破坏跨任务缓存键，也不要为增加命中而省略影响正确性的条件。

工具目录应能让模型发现合适能力；加载与执行的权限边界保持一致。MCP、函数调用、HTTP和Computer Use是接入/执行方式，不自动提供业务正确性或批准。

## 结果未知的最小处理

1. 记录已授权的确切动作意图、目标及可用执行回执；遵守现有并发控制。
2. 如果超时且不能证明未发生写入，保留结果未知，不立即重发。
3. 以相同业务身份进行有界回读，核对版本、字段、单位和记录状态。
4. 已保存且相符、明确未保存、保存不符、仍无法确认分别处理。未找到还可能来自分页、延迟或身份错误，先核对读范围。
5. 仅在现有合同允许且状态已查明时重试。当前任务授权不等于正式提交/支付/签发已批准。

回读确认的业务结果与旧任务检查点可能不同。通过原任务权威提供的接口关联回执并对账；接口缺失时分别报告两种状态，不直接改写权威记录制造“已恢复”。缺少原参数或来源快照时，只确认实际观察到的字段，不能宣称已与原请求完全一致。

审批仅用于产品和本次任务确实要求批准的动作。批准、编辑与拒绝关联具体参数；编辑后重新核验，拒绝后重规划不得绕开被拒动作。已授权的普通查询、可逆编辑和必要修复不附加确认门槛。

## 成果与完整性

按精确观察/来源引用选择数据，保留字段含义和单位。分页完整性按实际嵌套字段或覆盖证明判定；有限页面只能声明有限范围。最终文件回读、下载可用与内容/来源正确分别核验。模型文本中的路径、虚拟文件或“已保存”字符串不能代替真实成果。

对持久任务做需要的重启、重复请求、来源变化和权限变化样例。复用原有任务权威与审批状态；外部系统不支持可靠幂等时，诚实保留未知状态而不声称恰好一次。
