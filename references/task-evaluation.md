# 任务级验证与迭代

Skill 的结构检查不能证明其有效。用真实请求和允许的原始材料观察决策、产物与环境状态，避免只检查是否复述某段规则。

## 对比方法

选择同一组任务，对比不加载Skill、原版与新版；保持工具、资料、模型配置和预算可比。对高风险/复杂改动使用独立评审者，提供真实请求、Skill和最少原始材料，不泄露预期答案或先前结论。不能执行的动作只评价方案/决策，不记录为真实外部完成。

允许多种有效工具路径；主要判定任务结果、来源、覆盖、权限和副作用。记录耗时/费用与成功率，收益需有实际测量，不预先宣称节省比例。

## 有代表性的任务族

| 任务 | 可观察的验收目标 |
| --- | --- |
| 规则固定的简单查询/计算 | 完成当前交付；不增加无收益的框架、角色或审批 |
| 多来源表格与探索查询 | 最终选中范围明确，试探查询不混入；单位、版本与分页覆盖正确 |
| 保存超时 | 不盲目重写；按原动作身份回读，正确表达确认/未保存/不符/未知 |
| 来源换版与旧经验 | 重用方法但回源获取当前事实，识别失效依赖和旧批准范围 |
| 循环达到上限 | 记录终止与未通过，不用END或答案格式宣称成功 |
| 模型或stub自报成功 | 检查真实工具执行/成果/外部状态，识别模拟边界 |
| 会话或任务重启 | 依任务需要验证持久恢复；不以导出JSON或驱动存在代替实测 |
| 已授权的可逆修改 | 完成必要工作，不因Skill通用描述反复要求确认或扩大范围 |

## 四层验证

- 契约/单元：参数、状态迁移、计算、权限和错误分支是否符合当前合同。
- 实际服务：存储、worker、文件生成、回读和下载等真实链路。
- 模型执行：实际工具选择、参数修正、来源使用、预算与停止。
- 业务交付：专业人员确认的范围、数据、单位、公式、缺项与可用性。

按任务选必要层级，分别说明未验部分。一次小改动不自动触发整个平台重测；新失败、变更范围和未解决风险才扩大验证。评分器应有人工校准样本；同一路径重复、多个模型投票和自评不替代关键结果的独立数据路径。

## 更新规则

先修复已观察失败，再用保留样例和未见变体检查是否引入回归。记录Skill内容指纹、工具/模型/提示版本和来源。有限合成任务通过只支持该范围，不等于真实生产、付费模型或专业验收。
