# agent-des

用于设计、搭建、扩展和评审 AI Agent 的方法型 Skill。它从具体工作和交付结果出发，帮助把需求落实为可执行、可观察、可恢复、可验收的能力。

当前版本：**0.3.0** · 最近审查：**2026-10-20**

## 主要能力

| 工作 | 提供的帮助 |
| --- | --- |
| 定义任务 | 明确输入范围、允许动作、交付物、完成证据及失败或停止条件。 |
| 选择执行结构 | 根据任务选择确定性函数、固定工作流、Agent 循环或有收益的并行分工。 |
| 检查已有实现 | 沿真实调用链区分已实现、未接线、仅模拟、未验收和生产状态未知的能力。 |
| 设计工具 | 明确工具的输入输出、数据覆盖、来源版本、单位、副作用、回执和失败语义。 |
| 管理上下文与记忆 | 按任务读取必要细节，区分可复用方法、需回源的事实和执行状态。 |
| 处理耐久动作 | 复用宿主的持久任务、检查点、权限和审批机制，处理重试、中断及结果未知。 |
| 验证与交付 | 分层检查协议、实际服务链、真实工具轨迹与成果质量，说明证据和未覆盖部分。 |

优先检查现有实现，使用能完成任务的最短有效路径。增加角色、反思、图编排或迁移框架，需要明确收益和成本。

## 六个判断模型

1. **交付倒推**：先定义能被外部检查的最终状态，再设计步骤；流程结束仍需成果证据。
2. **复杂度按需**：固定规则交给程序，开放选择交给模型；每一层结构都应有实际用途。
3. **观察与事实分层**：模型提出调用、工具真实执行、结果满足要求，是需要分别核对的事实。
4. **状态各有权威**：计划、会话、执行、交付物和外部业务状态各自建模，并保留成功、失败、部分完成或结果未知的含义。
5. **记忆有适用期**：方法可以复用，当前事实需要回源；权限、来源和工具变化会使旧记忆失效。
6. **验收看结果**：根据风险和任务规模验证成果，区分运行成功与任务成功。

## 安装

在支持 Skills 的 Codex 环境中，可向内置安装器提出：

```text
$skill-installer 请从 https://github.com/suzhiyong23-afk/Agent-Des 安装仓库根目录的 agent-des Skill。
```

也可以手动克隆到用户级 Skills 目录。**若已有同名目录，请先检查其内容和来源，不要覆盖已有安装。**

macOS / Linux：

```bash
git clone https://github.com/suzhiyong23-afk/Agent-Des.git ~/.agents/skills/agent-des
```

Windows PowerShell：

```powershell
git clone https://github.com/suzhiyong23-afk/Agent-Des.git "$env:USERPROFILE\.agents\skills\agent-des"
```

仅用于某个项目时，也可以安装到该项目的 `.agents/skills/agent-des`。安装位置及使用方式参见 [Codex 官方 Skills 文档](https://learn.chatgpt.com/docs/build-skills)。

本仓库提供指令、方法和参考材料，没有固定的模型、SDK 或框架依赖。工具执行、委派、持久任务及权限控制取决于宿主环境；其他宿主的发现与安装方式需按其文档核对。

## 调用示例

检查已有 Agent：

```text
$agent-des 检查当前仓库的 Agent 调用链，区分已实现、未接通、模拟和未验收的能力，并给出有证据的改进建议。
```

设计并实现具体任务：

```text
$agent-des 为“收集指定资料并生成带来源的报告”设计最小可用方案，并在当前仓库中完成实现与相称验证。先明确输入范围、交付物和完成条件。
```

修复任务完成判定：

```text
$agent-des 这个 Agent 经常显示完成，但报告缺资料或引用错误。请沿工具执行和成果验收链路定位原因，修复问题，并用代表性失败样例验证。
```

提供现有仓库、真实失败样例、输入范围和预期成果，有助于获得更具体的设计或修复结果。
